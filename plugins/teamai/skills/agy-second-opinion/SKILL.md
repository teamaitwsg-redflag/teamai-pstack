# agy 第二意見

agy 是不同廠牌（Google Gemini）的模型，用途是抓 Claude 抓不到的錯。主對話的 Claude 仍是唯一的判斷者與驗收者：agy 的每個發現都要回原始資料或程式驗證後才採用。

以下的指令與行為是在 Windows、agy 1.5.8 上實測的（2026-11-13）。換版本或換作業系統後，先重測「能不能寫檔」「可用模型清單」這兩件事再照做。

## agy 預設可以寫檔

實測：不加參數時，agy 會真的寫出指定的檔案。一律加 `--mode plan`（實測可擋住寫入）。禁用 `--dangerously-skip-permissions`。

## 固定呼叫寫法

```bash
# Windows 的 Bash 裡找不到 agy 時先加這行
export PATH="$LOCALAPPDATA/agy/bin:$PATH"; export PYTHONUTF8=1

agy --mode plan --print-timeout 20m --add-dir "<資料夾>" \
    --model "Gemini 4 Hydrogen (XHigh)" \
    -p "只准使用 read_file 工具讀檔，禁止執行任何 shell 指令，禁止修改任何檔案。讀 <絕對路徑>，…" \
    > "<暫存目錄>/agy_review.txt" 2>&1
```

- 一定用 `--model` 指定 Gemini 的模型，名稱含括號要加引號。agy 也能選 Claude 的模型，但同廠牌不算獨立意見。可用模型清單用 `agy --model zzz-fake -p x` 列出。
- prompt 一定寫「禁止執行任何 shell 指令」，否則簡單的題目它也會去叫 shell 而失敗。
- 輸出導到檔案再讀。要看 stdout 的實際內容與大小，不能只看 exit code。
- 長文件要五到十分鐘，Bash 工具的 timeout 要設夠長。
- 逾時就換別的做法，不要重跑同一題。
- 搜尋題的 prompt 要寫：只准用 search_web、每個答案附來源網址、搜尋沒結果就明說。沒有來源網址的回答不採用。

## 審查 prompt 範本：程式碼

先把 diff 存成檔案（`git diff main...HEAD > <暫存目錄>/review.diff`）再給 agy 讀，不要讓它自己跑 git。

> 只准使用 read_file 工具讀檔，禁止執行任何 shell 指令，禁止修改任何檔案。讀 <repo 絕對路徑> 下的 <檔案清單或 diff 檔>。請以程式審查者身分回報：(1) 會造成錯誤結果或當機的邏輯錯誤；(2) 邊界條件與例外處理的漏洞；(3) 安全問題（注入、密鑰外洩、權限）；(4) 與現有程式碼風格或介面不一致的地方；(5) 缺少的測試。每項寫明檔案、行號、原文、建議與嚴重度；沒有問題的類別明說「未發現」。不要憑空推測，看不到的標「無法確認」。

## 審查 prompt 範本：文件

> 只准使用 read_file 工具讀檔，禁止執行任何 shell 指令，禁止修改任何檔案。讀 <檔案絕對路徑>（<頁數> 頁）。請以審稿人身分逐頁檢查並回報：(1) 錯字、用詞不一致；(2) 同一個數字在不同頁是否矛盾；(3) 表格加總是否合理；(4) 頁碼與章節參照是否正確；(5) 版面問題（文字被裁、重疊、圖文不符）。每項寫明頁碼、原文、建議；沒有問題的類別明說「未發現」。不要憑空推測，看不清的標「無法確認」。

## 收到結果之後

1. 把每個發現分成三類：已驗證屬實、驗證後不成立、無法確認。能用程式或原始資料驗的（數字、筆數、加總）一律用程式驗。
2. 屬實的修正後重新驗證；不成立的寫明理由；無法確認的列給使用者。
3. agy 說「無法確認」不代表沒問題，也不代表有問題。
4. agy 回報「未發現問題」不等於通過，它只是其中一道檢查。

## 不要做

- 不用 agy 做最終數字計算、寫入資料庫、產生交付檔。
- 不把密鑰、.env、含個資或客戶資料的檔案送給 agy。
- 不替使用者輸入任何密碼或授權碼。

## 安裝與登入（agy 不存在或登入失效時）

- 安裝要先得到使用者同意。Windows 的官方指令：`irm https://antigravity.google/cli/install.ps1 | iex`，裝在 `%LOCALAPPDATA%\agy\bin`。其他作業系統請使用者依 Google 官方說明安裝。
- 登入：`agy --print-timeout 15m -p "OK"` 會印出 Google 登入網址，授權碼只等 60 秒。先請使用者開好頁面再啟動，授權碼由使用者自己貼在終端機，不要請他貼在對話裡。
- 驗證：`agy --version`，以及 `agy -p "請只回答 OK，禁止執行任何 shell 指令"` 要真的印出 OK。
- 額度用完或授權錯誤時照實告訴使用者，不要反覆重試。
